API / read only

The dataset, as an endpoint.

Every published row is readable over HTTPS with a public, read-only key. Filter, sort, page and export the same 7,813 stays the site filters, as JSON or CSV. No sign-up, no secret.

The API is PostgREST over a Postgres table with row-level security. The key below is publishable and already shipped in the site's JavaScript. It grants read only. There is no server to run and no token to rotate for you.

04 / Filtering, sorting, selecting

Query parameters are PostgREST operators. Use them the way you would a SQL WHERE, plus an ORDER BY and a column list.

ParameterExampleMeaning
selectselect=name,district,ratingReturn only these columns. * returns all 48.
eq / neqdistrict=eq.IdukkiEqual / not equal.
gt / gte / lt / lterating=gte.4.5Numeric comparison.
indistrict=in.(Wayanad,Idukki)Match any value in a list.
ilikename=ilike.*tree*Case-insensitive pattern. * is the wildcard.
israting=is.nullNull check.
orderorder=rating.desc.nullslastSort. Append .desc or .asc, and .nullsfirst or .nullslast.
limit / offsetlimit=100&offset=200Page size and start row.

1,395 rows have no rating, so rating and review_count can be null. A descending sort puts nulls first by default. Add .nullslast to push them to the end, as the examples here do.

Example: highly rated pool stays in the hill districts, best reviewed first.

curl "https://lurkdmbjoapgimruktfs.supabase.co/rest/v1/resorts_enriched?select=name,district,rating,review_count&swimming_pool=eq.yes&environment_primary=eq.hill&rating=gte.4.5&order=review_count.desc&limit=20" \
  -H "apikey: sb_publishable_6RatKlW42cuc8koN45VB2g_pWMIFX7A"

05 / Paging past 1,000 rows

One request returns at most 1,000 rows. Walk the set with offset, in steps of 1,000, until a page comes back short.

offset=0, 1000, 2000, 3000, 4000, 5000, 6000, 7000  →  8 requests cover all 7,813

The response Content-Range header reports the slice and the total, for example 0-999/7813. To get a count without the rows, send Prefer: count=exact with Range: 0-0.

06 / JSON and CSV

JSON is the default. Ask for CSV with the Accept header. The same filters apply.

curl "https://lurkdmbjoapgimruktfs.supabase.co/rest/v1/resorts_enriched?select=*&district=eq.Wayanad" \
  -H "apikey: sb_publishable_6RatKlW42cuc8koN45VB2g_pWMIFX7A" \

Three fields are deliberately conservative and use not-sure rather than a guess: swimming_pool, food_included and campfire. affordability is a four-band estimate, not a price. No rupee value is stored anywhere.

08 / Limits and fair use

  • Read only. The key can select, not write. Inserts, updates and deletes are refused by row-level security.
  • Rate limited. The endpoint sits behind the project's anonymous quota. Keep calls bounded, page in 1,000s, and cache on your side.
  • Attribution. The underlying listing data comes from public sources. Credit Kerala Field Notes and link back to the repository when you republish.
  • No guarantees. The dataset refreshes as the enrichment and image jobs run, so row counts and image rows change. Treat this as an open, best-effort dataset, not a contract.

Need a private key?

This key is shared and public. If you need a personal key with its own quota, or a paid or higher-rate feed, open an issue on the repository.
